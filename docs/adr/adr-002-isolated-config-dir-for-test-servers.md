# ADR 002: Isolated Config Dir for Test Servers

## Status

Accepted

## Context

PetaJournalのサーバーは、`config.json` の `markdownDir` にページをMarkdownとして書き出す。また、そのフォルダの変更を監視してDBに取り込む。この往復同期が、サーバーの基本動作である。

E2Eテスト（`e2e/`）は、サーバーの実バイナリを一時ディレクトリで起動する。起動引数は `--data-dir` と `--index-dir` だけだった。`--config-dir` を渡していなかったため、テストサーバーは既定の `~/.peta-journal/config.json` を読んだ。その結果、テストが作った日記ページが、ユーザーの本物のMarkdownフォルダに書き出された。ユーザーのサーバーはその変更を取り込み、2026年10月15日から21日の日記がテストデータで上書きされた。

サーバーの設定は、データの置き場所（`--data-dir`）と設定の置き場所（`--config-dir`）が独立している。片方だけ一時ディレクトリにしても、もう片方は本物を指す。この分離が事故の土台になった。

## Decision

テスト用のサーバーは、必ず自分専用の設定ディレクトリで起動する。E2Eテストは一時ディレクトリの中に `config/config.json` を書き、`markdownDir` をその一時ディレクトリ内のフォルダにする。そして `--config-dir` でサーバーに渡す。

E2Eテストは、最初のテストを走らせる前に `GET /api/config` で `markdownDir` を確認する。一時ディレクトリの外を指していれば、スイート全体を中止する。

サーバーは、`--data-dir` が指定されて `--config-dir` が指定されていないとき、起動時に警告ログを出す。既定の設定ディレクトリを使うこと自体は変えない。通常の起動（引数なし）の動作を変えないためである。

`BUILD.md` に、手動で2つ目のサーバーを立てるときは必ず `--config-dir` を渡すことを書く。

## Alternatives

### Alternative 1: `--data-dir` を指定したら `--config-dir` も同じ場所を既定にする

サーバー側で、`--data-dir` が指定されたときは設定ディレクトリもその中に置く。E2Eの引数を変えなくても事故は防げる。しかし、データだけ別ドライブに置き、設定は `~/.peta-journal` のまま使う運用ができなくなる。既存の起動方法の意味が変わるため、選ばなかった。

### Alternative 2: E2Eテスト中はエクスポートを無効にする

テストサーバーを `--import-enabled false` と、エクスポート停止の新しい引数で起動する。書き出しが起きないので本物のフォルダは汚れない。しかし、E2Eがフォルダ同期を含む動作を検証できなくなる。また、引数を1つ忘れるだけで同じ事故が起きる構造は変わらない。そのため選ばなかった。

## Confidence Level

高い。対策は3層ある。E2Eの起動引数、テスト開始前の確認、サーバーの警告ログである。引数を1つ忘れても、確認がスイートを止める。

次の状況になったら見直す。サーバーが設定ファイル以外の場所（環境変数や別の設定源）から `markdownDir` を読むようになったとき。テスト開始前の確認は `GET /api/config` の値だけを見ているため、確認の対象を増やす必要がある。

## Consequences

良い結果。E2Eテストが本物のMarkdownフォルダに触れなくなる。テストサーバーの書き出しは一時ディレクトリの中に閉じる。`--config-dir` を忘れても、テスト開始前の確認がスイートを止める。

悪い結果。E2Eの設定が少し複雑になる。一時ディレクトリに `config.json` を書く処理と、グローバルセットアップが増える。

中立的な結果。サーバーを手動で2つ目として起動するときの作法が決まる。`--data-dir` と `--config-dir` をセットで渡す。片方だけなら起動時に警告が出る。

今回の事故で失われたデータは、1時間ごとの自動バックアップ（`~/.peta-journal-autobackup/`）から復元した。バックアップの間隔が、失われうる最大の時間を決める。
