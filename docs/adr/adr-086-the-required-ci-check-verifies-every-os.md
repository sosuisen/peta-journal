# ADR 086: The Required CI Check Verifies Every OS

## Status

Accepted

Supersedes ADR 084.

## Context

ADR 084は、PRの前に、ジョブが必要なOSのすべてで通ったことを確かめるために、Gitのnotesに記録を残すと決めた。
その前提は、「CIは手で起こし、料金がかかる」ことだった。
macOSのランナーはLinuxのおよそ10倍の料金がかかり、プッシュのたびにCIを回すのは現実的でなかった。
ADR 084は受理されたが、実装されていない。
`scripts/checks.mjs`に`oses`はなく、`refs/notes/peta-verify`もない。

### 前提が変わった

2026-11-25に、リポジトリは`petajournal` organizationから個人の`sosuisen`へ移り、publicになった。
publicのリポジトリでは、GitHubの標準のランナーは、macOSも含めて無料で無制限である。
これを受けて、`.github/workflows/ci.yml`は次のように変わった（#1156）。

- CIは、PRを作ったとき、PRへプッシュしたとき、`main`へプッシュしたときに、自動で回る。
- 最初の`plan`ジョブが、変わったファイルを`node scripts/checks.mjs jobs`に渡し、回すジョブを選ぶ。
  PRの前のフック（`.claude/hooks/verify-before-pr.mjs`）と同じ決まりである。
- 選ばれたジョブは、Linux、Windows、macOSのランナーで回る。
- 最後の`ci`ジョブが、ほかのすべてのジョブを待ち、1つでも失敗か中止があれば失敗する。
- `main`のルールセット`protect main`は、GitHub Actionsの`ci`のチェックを必須にしている。

### ADR 084が挙げた穴は、CIがふさいでいる

ADR 084が挙げた穴は3つあった。
今は、どれも必須のCIのチェックがふさいでいる。

- 手元の機械では、ほかのOSのジョブが回らず、issueのチェックボックスは回さずに付けられる。
  今は、CIがすべてのOSでジョブを回し、`ci`が通らなければPRをマージできない。
- チェックボックスは、どのコミットで確かめたかを持たない。
  今は、必須のチェックはPRの先頭のコミットのSHAに付き、コミットを足すとCIが回り直す。
- PRを作ったあとのプッシュは、検証されない。
  今は、PRへのプッシュのたびにCIが回る。

### フックが重い

フックは今、変わったジョブを、この機械のOSの段もほかのOSの段も回そうとする。
WindowsでmacOSの段に当たると、SSHで開発者のMac（`scripts/mac.mjs`）で回す。
`stickies-win`のカバレッジの段（`dotnet build -t:Coverage`）は、画面のテスト（`PetaScreens.Tests`）を含み、本当のキーを押す。
その間、開発者はPCに触れられない。
`ci.yml`や`scripts/`を変えると、すべてのジョブが回り、1時間ほどかかる。
CIが同じ確認をすべてのOSで行う今、フックでこれを待つ理由は小さい。

## Decision

必須のCIのチェック`ci`を、ジョブがすべてのOSで通ったことの証拠とする。
ADR 084のGitのnotesの記録は作らない。
PRの前のフックは、CIを待たずに失敗に早く気づくための道具として残し、軽くする。

### CI

CIは、PR、PRへのプッシュ、`main`へのプッシュのたびに、`plan`が選んだジョブを、すべてのOSのランナーで回す。
回すOSを、変わったファイルで絞ることはしない。
ジョブを選ぶのは`plan`だけである。
`main`のルールセットが必須にするのは、`ci`のチェック1つだけとする。
ジョブを足したり消したりしても、ルールセットを直さずに済むためである。

### フック

フックは、`gh pr create`と、PRを作るREST APIの呼び出しの前に動く（今と同じ）。
フックは、`jobsFor`が選んだジョブのうち、この機械のOSで回せる段だけを回す。

- ほかのOSの段は飛ばす。
  フックは、macOSの段をMacで回さない。
- 画面に触れる段も飛ばす。
  `scripts/checks.mjs`で、画面に触れる段に`screen: true`を書く。
  `stickies-win`のカバレッジの段がこれにあたる。
- 飛ばした段は、AIに知らせるだけで、PRは止めない。
  CIがその段を回すためである。
- この機械のOSの段で、プログラムや環境変数が用意されていないものは、今と同じく失敗させ、PRを止める。

フックは、PRを作ったあとの`git push`では動かない。
PRへのプッシュは、CIが確かめる。

### 手で回すとき

`node scripts/checks.mjs run <job>`を手で回したときは、印のある段も含めて、すべての段を回す。
WindowsでmacOSの段に当たれば、今と同じく`scripts/mac.mjs`でMacで回す。
CIを待たずに、SwiftのコードやWindowsの画面を試したいときに使う。

### 書き残し

飛ばした段を、PRの本文の「確かめていないこと」とissueのチェックボックスに書く決まりはやめる。
必須の`ci`のチェックが、その代わりになる。

## Alternatives

### Alternative 1: ADR 084を実装する

Gitのnotesに、ジョブとOSごとの記録をSHAごとに残し、フックが確かめる。
CIがなくても、手元とMacの結果だけで検証できる。
しかし、CIが無料ですべてのOSを回し、`ci`のチェックがマージを止める今、同じことを確かめる仕組みが2つになる。
notesは偽れるが、CIの結果は偽れない。

### Alternative 2: フックが今のまま、すべての段を回す

macOSの段もMacで回し、画面のテストも回す。
CIより先に、すべての失敗に気づける。
しかし、PCに触れられない時間とMacの準備が、PRのたびに要る。
CIが同じ確認をするので、得るものは待ち時間の差だけである。

### Alternative 3: フックをやめる

CIだけで確かめる。
仕組みは最も小さい。
しかし、整形やlintの失敗のような手元ですぐ分かる誤りも、CIを待たないと分からない。
CIの1回は、macOSのジョブで25分ほどかかる。

### Alternative 4: 変わったファイルに関わるOSだけでCIを回す

ジョブごとにOSを決め、関わるOSのランナーだけを使う。
しかし、`plan`がすでにジョブを絞っている。
共有のRustのクレートは、どのOSのジョブも選ぶので、OSでさらに絞っても減るものは小さい。

### Alternative 5: ADR 084を書き直す

受理したADRを、新しい決定に合わせて書き換える。
しかし、ADRは決めた時点の理由を残すものである。
書き換えると、なぜnotesを考え、なぜやめたかが残らない。

## Confidence Level

高い。

CIの自動の実行、`plan`によるジョブの選択、必須の`ci`のチェックは、#1155と#1156で動くことを確かめた。
`docs/`だけを変えたPRでも`ci`は通り、マージできた。

次のときは、この決定を見直す。

- リポジトリがprivateに戻るか、GitHubが標準のランナーの料金を変えたとき。
  CIを毎回回せなくなり、ADR 084の考え方に戻る。
- 大きいランナー（macOSの12コアなど）を使うジョブを足すとき。
  大きいランナーは、publicでも料金がかかる。
- CIの待ち時間が長くなりすぎ、フックで先に回す段を増やしたくなったとき。

## Consequences

### 良い結果

- ジョブがすべてのOSで通ったことを、偽れないCIの結果で確かめる。
- フックの待ち時間が短くなる。
  Macの準備がいらず、画面のテストの間PCを空けなくてよい。
- PRの本文とissueに、確かめていないOSを手で書く作業がなくなる。
- ADR 084のnotesの仕組みを作らずに済む。

### 悪い結果

- macOSと画面のテストの失敗は、PRを作ってCIが終わるまで分からない。
  macOSのジョブで25分ほどかかる。
- 失敗の直しは、PRへの追加のコミットになる。
- CIが落ちると、`ci`のチェックが通らず、マージできない。
  `protect main`にはバイパスがないので、CIそのものが壊れたときは、ルールセットから`ci`のチェックを外して直す。

### 中立的な結果

- `scripts/checks.mjs`の段に`screen: true`が増え、`scripts/verification.test.mjs`がその値を見張る。
- `stickies-win`の画面のテストを含まないテストを、フックで回したくなれば、カバレッジの段とは別の段に分ける必要がある。
- `scripts/mac.mjs`は、手で回すときだけ使われる。
- `verification`スキルの「確かめられなかったこと」と「フックで強制する」の節を、この決定に合わせて直す。
