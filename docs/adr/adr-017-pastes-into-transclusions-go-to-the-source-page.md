# ADR 017: Pastes into Transclusions Go to the Source Page

## Status

Accepted

## Context

トランスクルージョンは、別の項目の本文を写して表示する。写している項目を、ここではルート項目と呼ぶ。元の項目があるページを、参照元ページと呼ぶ。

ルート項目への入力は、元の項目に保存される。ルート項目自身は、本文を持たない。

貼り付けは、入力と違って、複数の項目になることがある。複数の段落は段落ごとの項目になり、Markdownのリストは入れ子を保った項目になる。そのため、ルート項目に貼り付けたときに、新しい項目をどのページに作るかを決める必要がある。候補は、参照元ページと、写している側のページの2つである。

## Decision

トランスクルージョンのルート項目への貼り付けは、必ず参照元ページに対する処理にする。

貼り付けは、基本的に入力と合わせる。入力は元の項目に保存されるので、貼り付けも元の項目に書く。

貼り付けが複数の項目になる場合も、新しい項目は必ず参照元ページに作る。貼り付けは、写している側のページには項目を作らない。

## Alternatives

### Alternative 1: 新しい項目を、写している側のページに作る

最初の断片だけを元の項目に書き、残りの項目は写している側のページに作る。貼り付けた項目は、貼り付けた画面にそのまま残る。しかし、1回の貼り付けが2つのページに分かれる。入力は元の項目に保存されるので、入力と貼り付けで書き込む先が食い違う。そのため、選ばなかった。

## Confidence Level

確信度は高い。入力と同じ規則なので、決まりは1つで済む。

次のときに見直す。

- ルート項目への入力を、元の項目に保存しない形に変えたとき。貼り付けは入力に合わせているので、一緒に考え直す。

## Consequences

良い結果は次のとおりである。

- 入力と貼り付けは、同じページに書く。ルート項目に対する書き込みの規則は、1つになる。
- 1回の貼り付けは、1つのページだけを変える。

悪い結果は次のとおりである。

- 貼り付けで作った項目は、参照元ページのものである。写している側のページには、その項目としては入らない。トランスクルージョンが見せている範囲に入らなければ、貼り付けた画面からは見えない。

中立的な結果は次のとおりである。

- サーバーの貼り付け（`POST /api/items/{id}/paste`、ADR 011）は、作る項目を、元の項目のページに、元の項目の階層を基準に作る。
- 貼り付けのあと、写している側のページは読み直す。サーバーは、写している側のページにも変更を知らせる。
