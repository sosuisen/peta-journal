# ADR 001: Tag Link Root Directory

## Status

Accepted

## Context

PetaJournalのアイテム本文に書いた `#topic` は、フロントエンドでリンクになる。これまでリンク先は `/pages/topic` に固定されていた。つまりタグページはページのルートに置くしかなかった。

PetaJournalのMarkdownフォルダは、そのままWebサイトとしてパブリッシュすることを想定している。サイト側ではタグページを `/tags/` のような専用ディレクトリにまとめたい。しかしリンク先がルート固定だと、エディタ上のリンクとサイト上のリンクが食い違う。タグページを `tags/` に置くと、エディタでは存在しないページへのリンクになる。ルートに置くと、サイト側でパスの書き換えが必要になる。

ページの置き場所は `dirPath`（`tags/` のように末尾が `/`）で表す。設定値もこの形式に揃えると、既存のパス処理と整合する。

## Decision

タグページのディレクトリをサーバー設定 `tagsDir` として持つ。値は `dirPath` 形式に正規化して `config.json` に保存する。先頭の `/` は取り除き、空でなければ末尾に `/` を付ける。空文字はページのルートを意味し、既定値とする。

フロントエンドはハッシュタグのリンク先を `/pages/{tagsDir}{tag}` にする。`tagsDir` が `tags/` のとき、`#topic` は `/pages/tags/topic` へリンクする。

設定は `GET/PUT /api/config` と MCPの `get_config` / `update_config` で読み書きする。設定画面にはテキスト入力を置き、保存後はサーバーが正規化した値を表示する。

## Alternatives

### Alternative 1: リンク先をルート固定のままにする

現状どおり `#topic` を `/pages/topic` にリンクする。実装は不要だが、パブリッシュ時にタグページだけパスを書き換える仕組みが必要になる。エディタとサイトでリンクの構造が食い違うため、選ばなかった。

### Alternative 2: タグページのディレクトリを `tags/` に固定する

設定を持たず、常に `/pages/tags/topic` にリンクする。もっとも単純だが、既存のタグページはルートにあるため互換性が壊れる。サイトごとにディレクトリ名を変えたい場合にも対応できない。そのため選ばなかった。

## Confidence Level

高い。設定は1つの文字列であり、リンク先の組み立ても単純である。既定値が空文字なので、既存のデータと動作は変わらない。

次の状況になったら見直す。タグページとWebサイトの対応が、ディレクトリ1つでは表せなくなったとき。たとえばタグの種類ごとに置き場所を分けたい場合や、サイト側のURL構造が `/pages/` と大きく異なる場合である。

## Consequences

良い結果。タグページを `tags/` のような専用ディレクトリにまとめられる。エディタ上のリンクとパブリッシュしたサイトのリンクが同じ相対パスになる。設定値を `dirPath` 形式に正規化するので、入力のゆれに悩まされない。

悪い結果。`tagsDir` を変えても、既存のタグページは移動しない。移動はユーザーが行う必要がある。変更前に書いたリンクは、ページの移動が済むまで新規ページを指す。

中立的な結果。設定項目が1つ増える。`config.json`、REST API、MCP、設定画面のそれぞれに `tagsDir` が加わる。

## 追記: 既定値を `tags/` に変更（2026-10-27）

`tagsDir` の既定値を空文字から `tags/` に変えた。`config.json` は各マシンのホームにあり、Markdownフォルダと違って同期されない。そのため、設定していないマシンだけがタグページをルートに作り、タグボタンもルートを開いていた。ルートに置きたいときは、空文字を明示して保存する。保存した空文字は既定値に戻らない。
