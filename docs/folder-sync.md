# Markdownフォルダの同期

ジャーナルサーバーは、データベースとMarkdownフォルダを双方向に同期する。複数のPCで使うときは、このフォルダをDropboxなどで共有する。サーバーどうしは直接通信しない。

具体的な流れは[folder-sync-journeys.md](folder-sync-journeys.md)、規則を決めた理由は[ADR 006](adr/adr-006-item-level-lww-for-folder-sync.md)にある。

## 同期のしくみ

- **DB → フォルダ**: 変更は、数秒後（既定では5秒ごと）に`{markdownDir}/docs/...`か`journals/...`に書き出される。
- **フォルダ → DB**: サーバーはフォルダを監視し、編集されたファイルをデータベースにマージする。
  - 各項目の前のコメント（`<!-- @ <id> idx="..." modified="..." -->`）で、項目を対応づける。変わっていない項目は、順序の値（`idx`）も含めてそのまま残る。
  - 両方にある項目は、項目ごとに`modified`が新しいほうを採る。そのため、2台のPCで同じページの別々の項目を編集しても、両方の編集が残る。
  - こちらで見ていないファイルの変更が負けたときは、そのファイルを`name.conflict-<日時>.md`として残す。
- **消えたファイルは、データベースから自動では削除されない。** ファイルが消えると、ブラウザで確認のページ（`http://localhost:8087/api/sync/pending-deletes`）が開く。
  - チェックして「Delete selected」を押したページだけが削除される。「Write selected back to the folder」で、フォルダに書き戻すこともできる。
  - 決めていないものが残っているあいだは、このページが開き直す（既定では、最短で5分おき）。

## Dropboxを使うときの注意

- フォルダを**オフラインで利用可能**にする。オンラインのみのファイルは、サーバーから見えず、確認のページに消えたファイルとして出ることがある。
- Dropboxの「競合コピー」（`a (PC's conflicted copy 2026-11-05).md`や`a (PC の競合コピー 2026-11-05).md`）は、元のページのもう1つの版として取り込まれ、そのあと消される。コピーから項目が消されることはない。
- 選択型同期で隠したフォルダや、同期が終わっていないフォルダは、確認のページに消えたファイルとして出る。チェックせずに残しておけばよい。

## 設定

同期の設定は、ジャーナルサーバーのフラグと環境変数で変える。一覧は[BUILD.md](../BUILD.md)の「Rust server」にある。

| フラグ | 既定値 | 意味 |
|---|---|---|
| `--export-interval` | 5 | DB → フォルダの書き出しの間隔（秒） |
| `--import-enabled` | true | フォルダ → DB の取り込みをするか |
| `--import-debounce-ms` | 2000 | ファイルが変わってから読むまで待つ時間（ミリ秒） |
| `--import-scan-interval` | 60 | フォルダ全体を調べ直す間隔（秒）。最初は起動の10秒後 |
| `--import-delete-prompt-cooldown` | 300 | 確認のページを開き直す最短の間隔（秒） |
| `--import-copy-wait` | 300 | 移動したページの古いファイルが消えるのを待つ時間（秒）。過ぎるとコピーとして取り込む |
| `--export-overwrite-wait` | 300 | まだ取り込んでいないファイルを上書きせずに待つ時間（秒）。過ぎるとファイルを`.conflict`に残して書き出す |
